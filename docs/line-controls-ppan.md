# LINE Controls — Ppan pilot

ฟีเจอร์นี้ทำงานเฉพาะ LINE user ที่จับคู่กับ `punpan_020` และต้องใช้ในแชตส่วนตัวกับ LINE OA เท่านั้น ระบบไม่รับ Advertiser ID, Business Center ID หรือ TikTok account ID จากข้อความ LINE แต่ดึงจาก config ที่อนุมัติไว้

## สถานะก่อนเชื่อม TikTok executor

- คำสั่งดูสถานะ, Shortcut, รายงานตามเวลา และตารางแจ้งเตือนคูปองทำงานจริง
- คำสั่งสร้าง/เปิด/พัก/เปิดใหม่/เปลี่ยนงบ/เปลี่ยน ROI เป็น `DRY-RUN`
- Auto Boost ส่งเหตุการณ์เพิ่มงบ/คืนงบตามเวลาจริง แต่เป็น `DRY-RUN` และไม่เรียก TikTok
- การยืนยัน DRY-RUN บันทึก audit แต่ไม่เรียก TikTok และไม่เปลี่ยนแคมเปญ
- เพดานงบ Ppan ยังคงเป็น 6,000 THB ต่อวัน
- ค่า `เติมเมื่อ X%` ใน Shortcut เป็นนโยบายที่บันทึกไว้สำหรับ executor รุ่นถัดไป ขณะนี้การแจ้งเตือนอัตโนมัติเดิมของ Ppan ยังใช้เกณฑ์ 80% จาก config หลัก

## คำสั่งหลัก

```text
Ppan
เมนู Ppan
สถานะ Ppan
วิธีใช้ Ppan
```

## รายงานตามเวลา

ตั้งรายงานทุก 2 ชั่วโมง:

```text
รายงาน Ppan ทุก 2 ชั่วโมง
```

หยุดรายงาน:

```text
หยุดรายงาน Ppan
```

รายงานแสดงงบปัจจุบัน, Cost, การใช้งบ, Gross revenue/ROI, Net revenue/ROI, GMV และเวลาที่ Chrome reader อ่านข้อมูล ระบบส่งตามรอบที่กำหนด แม้อยู่นอกช่วง LIVE โดยจะติดป้าย `ข้อมูลเก่า` เมื่อ snapshot เกินอายุที่อนุญาต และไม่ใช้ข้อมูลเก่าตัดสินใจเปลี่ยนแคมเปญ

## สร้างหรือแก้ Shortcut

ส่งหนึ่งข้อความ 5 บรรทัด:

```text
ตั้ง shortcut Ppan main
ชื่อ {date} {start}:00
งบ 3000
ROI 3.5
เติมเมื่อ 80%
```

- `{date}` แทนวันที่บัญชีตามเวลา Bangkok เช่น `2026-07-20`
- `{start}` แทนเวลาเริ่ม LIVE ที่อนุมัติไว้ เช่น `06:00`
- ระหว่างที่ Ppan ยังอาศัย Chrome reader รูปแบบชื่อถูกจำกัดเป็น `{date} {start}:00` เพื่อให้ตัวอ่านหาแคมเปญได้แน่นอน ชื่ออิสระจะเปิดหลัง API คืน Campaign ID และระบบผูก ID นั้นสำเร็จ
- การแก้ Shortcut ชื่อเดิมจะสร้าง revision ใหม่ ไม่แก้ revision เก่าย้อนหลัง
- งบต้องอยู่ระหว่าง 100–6,000 THB
- Target ROI ต้องอยู่ระหว่าง 0.1–100
- จุดเติมงบต้องอยู่ระหว่าง 10–95% และในรุ่นนี้เป็นค่าที่เก็บ/Preview เท่านั้น ยังไม่แทนเกณฑ์แจ้งเตือน 80% ของ Ppan

ดู Shortcut:

```text
ดู shortcut Ppan
```

สร้าง/เปิดแคมเปญจาก Shortcut (DRY-RUN จนกว่า executor จะพร้อม):

```text
เปิด Ppan main
```

```text
ตั้งงบ Ppan 2500
ตั้ง ROI Ppan 3.5

```

ทุกคำสั่งมี Preview และปุ่มยืนยันแบบ versioned/หมดอายุได้ ข้อความ LINE แสดงเฉพาะท้าย Ad account และไม่เปิดเผย ID เต็ม

## Coupon Boost

ตัวอย่าง: คูปองเริ่ม 20:00 ให้เตือนก่อน 30 นาทีและเตรียมงบ 5,000 THB

```text
คูปอง Ppan 2026-07-21 20:00 ก่อน 30 นาที งบ 5000
```

กดยืนยันการตั้งเวลาตอนที่สร้างรายการได้เลย ระบบเก็บตารางเวลาไว้ในฐานข้อมูลถาวรและกู้ต่อหลัง restart ได้ ในช่วงก่อนเชื่อม TikTok executor ระบบส่ง reminder + DRY-RUN preview เมื่อถึงเวลา หลังเชื่อม API แล้วจึงเปลี่ยนเส้นทางนี้เป็น pre-approved execution พร้อมตรวจงบก่อนและอ่านค่ากลับหลังเขียน

ยกเลิกรายการที่ยังรอ:

```text
ยกเลิกคูปอง Ppan
```

## Auto Boost ก่อนช่วงแคมเปญ

ส่งทุกช่วงเวลาในข้อความเดียว:

```text
ตั้ง Auto Boost Ppan
งบฐาน 3000
เพิ่ม 10%
ก่อน 10 นาที
ช่วงเวลา
12:00-13:00
15:00-16:00
20:00-21:00
```

กติกา Pilot:

- ตารางทำซ้ำทุกวันตามเวลา Bangkok จนกว่าจะกดปิด
- Pilot ยอมรับเฉพาะ `เพิ่ม 10%` และ `ก่อน 10 นาที`
- เป้าหมายคำนวณจากงบฐานเสมอ เช่น 3,000 → 3,300 ทุกช่วง จึงไม่ทบต้น
- ระบบจำลอง Boost ก่อนเวลาเริ่ม 10 นาที และจำลองคืนงบฐานเมื่อจบช่วง
- ระบบส่งข้อความคืนงบเฉพาะเมื่อเหตุการณ์ Boost คู่กันสำเร็จแล้ว หากพลาดเวลา Boost จะข้าม Restore เพื่อไม่รายงานสถานะที่ไม่เคยเกิดขึ้น
- Restore ของรอบที่ Boost สำเร็จแล้วไม่มีเวลาหมดอายุ หาก Render หรือ LINE ขัดข้อง ระบบจะกลับมาลองต่อเมื่อบริการฟื้น
- หาก worker หยุดหลังเริ่มส่ง Boost แต่ก่อนบันทึกผล ระบบเก็บสถานะ `OUTCOME_UNKNOWN` และทำ Restore แบบเผื่อไว้เสมอ แทนการสรุปเองว่า Boost ไม่เกิด
- ระบบไม่เริ่ม Boost รอบถัดไป (รวมวันถัดไป) จนกว่า Restore ที่จำเป็นก่อนหน้าจะเสร็จ เพื่อไม่ให้ Restore ที่มาช้าลดงบกลางช่วงใหม่
- ช่วงเวลาต้องอยู่ภายใน LIVE 06:00–23:00 และตั้งได้สูงสุด 24 ช่วง
- หากช่วง Boost ที่มีเวลานำ 10 นาทีทับหรือแตะกัน ระบบรวมเป็นช่วงต่อเนื่องเดียว เพื่อไม่คืนแล้วเพิ่มซ้ำ
- หากงบช่วงพิเศษเกินเพดาน 6,000 THB ระบบจะปฏิเสธ ไม่ลดหรือบีบยอดให้อัตโนมัติ
- การบันทึกตารางใหม่เริ่มเป็น `OFF` เสมอ และต้องปิดก่อนจึงจะแก้ตารางได้
- เมื่อกด `OFF` ระบบยกเลิกเฉพาะรอบ Boost ในอนาคต หากรอบใด Boost เริ่มแล้ว ระบบจะคง Restore ของรอบนั้นไว้จนจบ และยังไม่อนุญาตให้แก้ตารางหรือเปิดรอบใหม่ก่อน Restore เสร็จ
- การเปลี่ยนนโยบายหรือถอนสิทธิ์ผู้ตั้งภายหลังจะไม่ลบ Restore ที่จำเป็น; ระบบส่งการแจ้งเตือนไปยังผู้อนุมัติปัจจุบัน หากไม่มีผู้อนุมัติจะบันทึกผล DRY-RUN ไว้ใน audit โดยไม่ส่งข้อมูลไปยังผู้ที่ถูกถอนสิทธิ์
- LINE จะข้ามไปลองผู้อนุมัติรายถัดไปเฉพาะเมื่อ API ระบุชัดว่า `to` ไม่ถูกต้อง; 401/403, payload error, transport, 429 และ 5xx จะไม่ถูกตีความว่าเป็นผู้รับเสีย แต่คง Restore barrier พร้อม audit เพื่อรอแก้ไข/ลองใหม่
- รุ่นนี้แจ้ง LINE ว่า `DRY-RUN Auto Boost` และ `DRY-RUN คืนงบ Auto Boost` ตามเวลา แต่ไม่อ่าน/เขียนงบ TikTok ผ่านคำสั่งนี้

ดูสถานะและใช้ปุ่มใน LINE เพื่อสลับ ON/OFF:

```text
ดู Auto Boost Ppan
เปิด Auto Boost Ppan
ปิด Auto Boost Ppan
```

เมื่อปิด ระบบจะยกเลิกเหตุการณ์ DRY-RUN ที่ยังไม่ถึงเวลา การเปิดใหม่จะสร้างรอบใหม่โดยไม่เล่นซ้ำเหตุการณ์จากรอบ ON เดิม ตารางและสถานะเก็บในฐานข้อมูลและกู้ต่อได้หลัง restart
